## P0 · Analysis and success criteria

The visitor has a project in mind and wants to know whether Tech Bizz can help. The current app repeats a large brand header on all three tabs, gives its two Home buttons equal weight, and presents similar blocks of copy everywhere. The main action changes tabs and scrolls to Contact. Leadership sits below the company text. The app also renders feed casing literally, including “why choose us” and “E-commerce Solution.” These findings come from the three routes, shared `company/ui.tsx`, and the company content tree. They are design observations. There is no conversion baseline.

The redesign brings a useful headline and one primary action into the first Home viewport, lets visitors inspect services without reading a wall of text, and puts the CEO’s profile alongside the company introduction. Keep Home, Services, and Company as the only tabs. A new visitor should be able to name what Tech Bizz offers and open the channel chooser in one tap from Home. Use genuine content only. Add a Work destination once there is a case study the company can publish.

## P1 · Visual system and implementation order

1. Move Home, Services, and Company route files into `src/app/(tabs)/`. Add `(tabs)/_layout.tsx` to render the existing platform-specific `AppTabs` components with three tabs in their current order. Keep public URLs and API routes. Wrap the tabs, detail route at `src/app/services/[slug].tsx`, and contact at `src/app/contact.tsx` in the root Stack inside the existing theme, splash, and query provider. Give the detail a Stack title. Use `anchor: '(tabs)'` for direct native modal entry. Open contact as a native `formSheet` at 60% or full height with scrollable content. Use the normal Stack screen on web so the URL works after reload and browser Back works. Support legacy `/company?section=contact` by replacing it with `/contact` before rendering Company content. Remove old scroll refs and layout callbacks used only for that intent. Keep all new support files outside `src/app`.
2. Add shared theme tokens in `src/constants/theme.ts` and apply them to the app shell, tabs, and new screens. Light uses canvas `#FAF8F4`, surface `#FFFFFF`, text `#211B17`, muted text `#625A52`, divider `#DED6CB`, and action `#B43B18` with white text. Dark uses canvas `#171411`, surface `#23201C`, text `#F6F0E8`, muted text `#C2B7AB`, divider `#413A33`, and action `#FF9B70` with `#211B17` text. Use system typography with sizes 34/40 for the hero, 26/32 for page titles, 20/26 for sections, 16/24 for body, and 14/20 for supporting copy. Use 20 horizontal padding on phones and 32 on wide layouts, a centered 720 maximum content width, 32 between sections, and 12 within groups. Keep service rows in one column with dividers. Use 48 minimum action height. The primary action, headlines, and portrait establish the visual hierarchy. Avoid repeated card backgrounds. Keep default font scaling, let text wrap, and make the sheet scrollable at full height. Ensure real safe area insets on each platform and visible keyboard focus on web.
3. Break `src/components/company/ui.tsx` into focused modules as they gain callers. Start with `screen-shell.tsx` → `ScreenShell`, `service-row.tsx` → `ServiceRow`, `leadership-card.tsx` → `LeadershipCard`, `contact-options.tsx` → `ContactOptions`, and `content-status.tsx` → `ContentStatus`. Use PascalCase for components and their props types, kebab-case for files and route segments, and camelCase for hooks and local values. Reserve route casing for Expo conventions such as `_layout.tsx` and `[slug].tsx`. Use semantic heading variants and distinguish navigation links from action buttons in accessibility roles. Remove superseded exports and files after migrating callers. Keep the existing standalone icon resolver.
4. Reuse the existing company and personal hooks, query cache, Zod parsers, and API proxies. Scope loading placeholders and retry UI to the affected section. Keep last-good content visible. Opening or closing contact and opening a service detail use the same company cache. Personal still starts on first Company focus. Reserve image space and use `expo-image` for the existing company assets. Keep portrait fallback initials. Use the existing logo for the wordmark and omit feed placeholder service images. Use platform transitions and avoid network fonts, autoplay, animation packages, new dependencies, and data contract changes.
