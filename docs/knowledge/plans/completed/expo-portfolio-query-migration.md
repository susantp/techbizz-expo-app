## P0 · Scope and standards

Replace the complete handwritten portfolio request lifecycle with TanStack Query v5. Preserve all three routes, the Zod contracts and typed results, the single JSON caller, content, contact behavior, and Expo web proxy contracts. Apply the [handoff checklist](../../topics/plan-handoff.md), [API contract and typing guide](../../topics/api-contracts-and-typing.md), and [library and state guide](../../topics/library-and-state-choices.md).

Use Jotai for shared mutable client state when a feature requires it. The Company focus flag, contact error, image failure flags, and scroll refs are screen or component state. Keep them local. The router owns the contact intent. TanStack Query owns remote data, and no Jotai dependency is needed in this migration.

## P1 · Implementation

1. Run `git status --short` and `git log -3 --oneline`. Preserve unrelated edits. Install `npx --no-install expo install @tanstack/react-query@5.107.1 --npm`. Registry peer metadata for this version accepts React 18 or 19, and the Expo checkout uses React 19. Inspect the manifest and lockfile diff for scope.
2. In `src/lib/portfolio/request.ts`, replace the tagged-result function with `fetchCompanyContent(signal?: AbortSignal): Promise<CompanyContent>` and `fetchPersonalContent(signal?: AbortSignal): Promise<PersonalContent>`. Both use one private `getPortfolioPayload(source, signal)` that resolves the existing web or native URL and calls `getJson`. Each public function parses with its matching schema and returns the inferred model. Keep the fetch call in `src/lib/remote/get-json.ts`. Keep the Zod model and web handler behavior, including forwarding original valid JSON and preserving 502/503 and no-store.
3. Add `src/lib/portfolio/queries.ts`. Define two `queryOptions` entries, keys `['portfolio', 'company']` and `['portfolio', 'personal']`, with each `queryFn: ({ signal }) => fetch…Content(signal)`. Both use `staleTime: Infinity`, `gcTime: Infinity`, `retry: false`, `retryOnMount: false`, `refetchOnMount: false`, `refetchOnWindowFocus: false`, `refetchOnReconnect: false`, and `networkMode: 'always'`. These match session caching and manual retry, including surfacing offline errors. Do not put these policies in global defaults for unrelated features.
4. Add `src/lib/portfolio/query-provider.tsx` and mount its provider where `PortfolioProvider` was in `src/app/_layout.tsx`. Use `useState(() => new QueryClient())` for one client per mounted app root. Inside the `QueryClientProvider`, mount two disabled query observers until root teardown. In an effect, start the company query with `queryClient.prefetchQuery(companyContentQuery)`. This starts fetching after mount, including direct route loads, without setting React state from an effect. The disabled personal observer keeps a subscription alive so a Company tab unmount cannot abort an active request. The Company screen keeps its existing focus flag as the only personal trigger. On root teardown the last observers unsubscribe and TanStack cancels in-flight requests through the consumed signal. Avoid a module singleton and avoid network work during server rendering.
5. Add `src/lib/portfolio/hooks.ts` exporting the existing `useCompanyContent()` and `usePersonalContent(enabled)` interface. The company screen hook observes the company query with `enabled: false` because the root starts it. Personal observes its own query with `enabled` from the existing first-focus flag. Use a small generic adapter for the two hooks with `{ data, status, error, retry }`: while `isFetching`, return loading and suppress the previous error; otherwise prefer error when `isError` even if data exists, then ready when data exists, and idle otherwise. Keep last good data visible during a request and after failed refresh. Manual retry calls `refetch({ cancelRefetch: false })` so repeat calls join the active request.
6. Switch imports in `src/app/index.tsx`, `services.tsx`, and `company.tsx` to the new hooks and delete `src/lib/portfolio/provider.tsx`. Preserve rendering, screen copy, focus, and the contact route. Search for stale imports and verify `rg -n '\\bfetch\\(' src` finds only the shared caller. Update the Expo project note and the API and library guides to reflect the new ownership. Keep file-specific implementation detail in the plan and relevant topic notes.
